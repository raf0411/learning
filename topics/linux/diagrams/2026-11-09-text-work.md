## Reading an option with a required argument

The completed manual exercise used this syntax:

```text
Manual:       -t char
               |  |
               |  +-- placeholder: supply a delimiter character
               +----- option token

Command:      join -t ',' departments.csv tickets.csv
                      |
                      +-- actual option argument: a comma
```

The shell removes the quote characters; `join` receives the comma. Here the
delimiter controls both input field separation and output field separation.
Rows pair by their matching first field, with that key appearing once in output.

```text
departments.csv       tickets.csv        joined output
ada,Design     +      ada,4       -->    ada,Design,4
```

The learner independently recovered the option syntax, constructed the command,
and predicted the observed result. The next exercise checks report construction
with new data.

## Report selection repair

```text
Pattern       PASS,Search,morning     PASSIVE,Search,standby
^PASS         matches                matches
^PASS,        matches                excluded
```

The comma marks the end of the first field in this dataset. A start anchor
alone establishes where the match begins, not where the field ends.

The corrected report contains `4 cache`, `3 queue`, and `1 search`.
Lowercasing before grouping makes mixed-case names count together. The learner's
sort-before-cut order works here because every selected, normalized row begins
with the same `pass,` field, so sorting full rows groups their component field.
That ordering would need reconsideration if multiple different statuses were
included. No additional written explanation was required from the learner.
