# Resources

Use the cheapest reliable source that resolves the question. During labs, prefer
observed machine output and installed documentation before external references.

## Curriculum coverage check

- [Linux Foundation Introduction to Linux (LFS101)](https://training.linuxfoundation.org/training/introduction-to-linux/)
  — primary beginner-level breadth check. Its outline covers command-line work,
  documentation, processes, file operations, editors, the user environment,
  text manipulation, networking, Bash scripting, and local security principles.

## Primary teaching references

- Installed `--help`, shell `help`, `man`, `info`, `/usr/share/doc`, and package
  documentation — first external-memory tools to practice on the actual system.
- [GNU Coreutils manual](https://www.gnu.org/software/coreutils/manual/coreutils.html)
  — upstream reference for GNU file, text, and system utilities.
- [GNU Bash manual](https://www.gnu.org/software/bash/manual/bash.html)
  — upstream shell behavior and scripting reference.
- [Linux man-pages project](https://www.kernel.org/doc/man-pages/)
  — Linux interfaces, file formats, and administrative command semantics.
- [systemd manual index](https://www.freedesktop.org/software/systemd/man/latest/)
  — upstream reference for basic service and journal behavior.
- [Ubuntu Server documentation](https://ubuntu.com/server/docs/)
  — official Debian-family package and Linux usage guidance.
- [Red Hat Enterprise Linux documentation](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/)
  — official Red Hat-family package and Linux usage guidance.

## Source policy for lessons

1. Actual disposable-lab output establishes what happened on the learner's host.
2. Installed manuals establish version-matched command behavior.
3. Official upstream documentation establishes tool and shell semantics.
4. Official distribution documentation establishes integration and packaging.
5. The LFS101 outline checks beginner breadth; performance is established through
   prediction, hands-on use, troubleshooting, retention, and transfer.
