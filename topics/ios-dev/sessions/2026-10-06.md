## Class `let` and model bindings

- Correctly said a child `let ShoppingList` reference does not prevent calling
  `remove`; tutor refined that `let` prevents reference reassignment, while the
  class instance can mutate and `private(set)` separately blocks direct external
  array mutation.
- In a `Profile` probe, initially offered `profile.nickname` to a TextField and
  reasoned that a class reference was sufficient. Tutor introduced
  `@Bindable var profile` and `$profile.nickname`.

  `$profile.nickname` is the binding connection, and TextField requires a
  `Binding<String>`. Exact ownership and two-direction update flow remain to be
  demonstrated in code.
