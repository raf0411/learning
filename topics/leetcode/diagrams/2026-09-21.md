## Keeping the best candidate so far

Start with the first element of the nonempty list. This is a valid candidate even if every number is negative.

```text
current number > stored largest?
           /             \
         yes              no
          |                |
   replace stored       keep stored
          \                /
           examine next number
```

After each iteration, the stored value is the largest among the elements examined. If the current number is larger, replacing the stored value preserves this property; otherwise keeping it preserves the property. When every element has been examined, the stored value is the largest in the whole list.

## Why starting at zero failed

Zero is not a valid initial candidate for every input. For an all-negative list, no element exceeds zero, so that version would return zero even though zero is not in the input.

The corrected initialization is:

```python
current_largest_number = numbers[0]
```

The loop still visits the first element. Comparing it with itself simply leaves the stored value unchanged.

## Input contract

This function assumes at least one element. An empty list has no first element; empty-input behavior would need a separate requirement.

## Counting numbers above a threshold

In `count_above(numbers, threshold)`, the tracked value has a different meaning: it counts qualifying elements already examined. Each occurrence strictly greater than the threshold contributes one.

Before examining any elements, the count is zero. This is true even if the input contains negative numbers: the variable stores a count, not an input value.

```text
Start count at 0
       |
For each number: greater than threshold?
                   /             \
                 yes              no
                  |                |
             add 1 to count    keep count
                   \             /
                    next element
       |
Return count
```

If the input is empty, the loop body executes zero times and the function returns the initial count of zero. A separate empty-list branch is unnecessary here.

Python lists use `len(numbers)` for length; they do not have a `.size` attribute.
