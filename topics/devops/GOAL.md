# GOAL

## Immediate career goal

Become employable primarily for an entry-level DevOps Engineer, Junior Cloud
Infrastructure Engineer, InfraOps Engineer, Cloud Operations/Support Engineer,
or closely related role within roughly 3–4 months (target: late November to
late December 2026).

Linux Administrator, SysAdmin, and infrastructure-support roles remain useful
secondary entry routes, but the curriculum should optimize for DevOps and cloud
delivery work rather than treating those as distant follow-on topics.

## Job-ready outcomes

By the end of this roadmap, I should be able to:

- administer an Ubuntu server safely from the command line;
- manage files, users, groups, permissions, packages, processes, and services;
- troubleshoot essential TCP/IP, DNS, HTTP/HTTPS, ports, routing, firewalls, and
  SSH using evidence rather than random changes;
- use logs and system tools to diagnose common service, resource, storage, and
  connectivity failures;
- understand the basic software-delivery lifecycle from source change through
  build, test, artifact, deployment, observation, and rollback;
- use Git confidently and automate routine operational work with Bash, adding
  basic Python where it provides clear practical value;
- package and operate a small service with Docker, including image builds,
  container configuration, networking, persistent data, and registries;
- build, inspect, and repair a basic CI/CD pipeline using GitHub Actions or an
  equivalent commonly used system;
- manually operate core AWS compute, networking, storage, IAM, and monitoring
  services, with enough GCP vocabulary to interpret mixed-cloud roles;
- provision a small cloud environment reproducibly with Terraform and safely
  inspect, change, and destroy it;
- configure monitoring, logging, alerts, access controls, updates, backups, and
  recovery for a small deployed service;
- demonstrate the complete workflow through documented portfolio projects,
  runbooks, and incident notes that explain the evidence and decisions made.

## Success evidence

Job readiness should be demonstrated through independent work, not a checklist
of tools. At minimum, the portfolio should show that I can:

- operate and troubleshoot a Linux-hosted service;
- containerize the service and deliver it through a working CI/CD pipeline;
- provision its AWS infrastructure with Terraform;
- secure, observe, back up, restore, and deliberately troubleshoot it;
- recover from at least several unfamiliar failures and document the root cause,
  verification, rollback, and prevention steps.

## Constraints and priorities

- Available study time: about 5 hours daily.
- Practice environment: macOS plus an Ubuntu homelab server.
- Prefer hands-on labs and troubleshooting over passive study.
- Preserve Linux, networking, security, and troubleshooting as the foundation;
  they are part of DevOps/Cloud competence, not a separate detour.
- Use AWS as the primary cloud platform. Learn only enough GCP terminology to
  understand common role descriptions until the AWS foundation is reliable.
- Introduce Git and automation early; make Docker, CI/CD, cloud, Terraform, and
  observability core outcomes rather than optional extras.
- Learn tools through one connected delivery-and-operations workflow rather than
  as isolated tutorials.
- Defer deep Kubernetes, multi-cloud operation, advanced configuration
  management, and advanced infrastructure-as-code patterns until the entry-level
  exit gate is passed. Basic Kubernetes concepts may be added near the end if
  time and demonstrated foundations allow.
