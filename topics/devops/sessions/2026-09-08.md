## Concepts covered

- Running, stopped, and terminated are process states; foreground and
  background describe terminal placement.
- After `Ctrl+Z`, the process remains alive but stopped. Once the shell retakes
  the terminal, the stopped job is technically a background job, although it
  is not running in the background.
- `bg` resumes a stopped job in the background and leaves the prompt available.
- `fg` resumes or moves a job into the foreground, causing the shell to wait.
- A trailing `&` is a shell operator that starts a command as a running
  background job; it is not an option belonging to `sleep`.
- A shell job number/jobspec and an operating-system PID identify related but
  different layers.
- `Ctrl+C` delivered `SIGINT` to the foreground `sleep`; the signal's default
  disposition terminated it. This does not mean every process must terminate
  whenever `Ctrl+C` is pressed.
- Application cleanup is work and therefore requires the process to execute
  further instructions.
- `SIGTERM` gives a process an opportunity to handle the request and clean up;
  its default disposition is termination.
- `SIGKILL` cannot be caught or ignored, so it does not permit application
  cleanup code to run.
- Plain `kill PID` sends `SIGTERM` by default. The safe operational pattern is
  cooperative request, wait and verify, then forced termination only if needed.

## Concepts requiring review

- `fg` means foreground and makes the shell wait; `bg` means background and
  leaves the prompt available.
- A stopped job may still be in the background; stopped does not mean
  terminated.
- Signal delivery remains distinct from the receiving process's disposition.
- `SIGTERM` provides a cleanup opportunity; `SIGKILL` does not.
- A successful signal-sending command does not replace checking whether the
  target process actually exited.
