## Concepts covered

- A successful `kill` command reports that the kernel accepted the
  signal-sending operation; it does not prove the target process exited.
- Signal delivery and the receiving process's outcome are separate events.
- With no custom handler, `SIGTERM`'s default disposition terminates the
  process.
- A handler that returns allows interrupted execution to continue; cleanup
  alone does not imply exit.
- A handler that explicitly exits terminates the process after cleanup.
- The safe escalation flow is: send `SIGTERM`, wait, inspect, send `SIGKILL`
  only if the process remains, then inspect again.
