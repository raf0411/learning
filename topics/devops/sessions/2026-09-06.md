## Concepts covered

- A program can exist as executable instructions on disk without a process.
- A process is a running instance of a program.
- Static program and unit files are passive; processes are runtime actors.
- A daemon is a background service process. It is intended to be long-running,
  but it can exit, fail, receive a signal, or be stopped.
- The system `systemd` process is the persistent manager at PID 1; `systemctl`
  and `systemd-run` are temporary clients that send it requests.
- A unit file is passive configuration, a service unit is systemd's managed
  runtime abstraction, and an associated daemon is a separate process.
- A service can have one process, several processes, or no continuing process;
  a `Type=oneshot` unit with `RemainAfterExit=yes` can be `active (exited)`.
- `ExecStart=` identifies what to start, while `Restart=on-failure` supplies a
  restart policy that the running manager applies.
- A transient unit is created for the current runtime rather than installed as
  a persistent service definition.
