## Concepts covered

- One numeric digit encodes one `rwx` triplet by summing `r=4`, `w=2`, and
  `x=1`; three digits encode owner, group, and other independently.
- Account creation and `sudo` authorization are separate operations.
- Ubuntu's `adduser` is a higher-level administrative interface while
  `useradd` is lower-level and more dependent on explicit options/defaults.
- Accounts have one primary group and may have supplementary groups;
  `usermod -aG` appends rather than replacing supplementary memberships.
- Updating group records does not retroactively change credentials held by an
  already-running process.
- A service identity needs UID/GID credentials but does not inherently need a
  password, human home directory, interactive shell, or `sudo`.
- `systemd` manages service units and starts configured programs as processes;
  `/usr/sbin/nologin` blocks the login-shell path, not direct program execution.
- File `w` controls content modification, while parent-directory `w+x`
  controls creating, deleting, and renaming directory entries.
- A real newline ends a shell submission; terminal visual wrapping does not.

## Concepts requiring review

- For basic permissions, deletion requires `w+x` on the parent directory;
  directory `x` alone only permits traversal/search.
- Separate database membership from the credentials held by existing
  processes.
- Keep long commands on one physical line or use an explicit continuation;
  never press Enter merely because the terminal visually wraps.
- Parse `sudo -u USER -- COMMAND` versus login-style `sudo -iu USER`.
- Distinguish `systemctl`, `systemd`, a service unit, a program, and a process.
